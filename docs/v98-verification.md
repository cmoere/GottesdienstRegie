User reports continuous editor/design slowness and cloud upload error `UPLOAD_PERMISSION_REQUIRED`. The initial reliability stage was committed as 7e92e76. ## Confirmed causes and fixes

- Slide/element edits previously replaced unrelated item references, normalization recreated every item and unchanged thumbnails rendered on parent updates. Regression tests fail before each correction. Unchanged references and memoized rendering now avoid that work; actual slide edits and independent live-element subscriptions remain observable.
- Design audit entries embedded both entire presentations. New slide edits include only changed items; before values remain redacted and ordinary undo snapshots remain intact. Existing whole-presentation slide audit entries are compacted without changing history IDs, metadata or changed item values. Other history shapes/types are preserved.
- Read-only check of an existing presentation: 24 slides, 291 audit entries. Original history 35,080,688 UTF-8 bytes; compacted history 2,889,312 bytes, with 171 compacted entries. Every omitted item was independently compared to its identical opposite-side value, all retained changed values and metadata were compared, presentation items were hashed, and the original source-file hash was rechecked unchanged. No source document was written by this probe. Proof: `work/v98-history-probe.json`.
- Now-playing and upcoming-event design changes previously updated item settings and one loop element separately. They now commit settings and loop properties together for every item slide. Linked copies retain their own slide, element and item IDs. Regression tests check one undo and linked identities.
- Concurrent media imports/metadata writes collided on the same temporary index and lost updates or failed. Repository mutations now serialize; failed operations do not poison the queue. Eight concurrent imports and overlapping favorite/usage/sync changes pass.
- Cloud permission errors now use the existing translated explanation and preserve the staged source for retry. A completed media list no longer waits for the optional status request; outdated responses cannot overwrite a subsequently selected tab. Cloud-list errors remain errors rather than a false successful empty list.
- Git credential queries formerly had no deadline, could prompt, forced the repository owner as login name, and depended on Git being visible to the GUI. They are bounded/noninteractive, coalesced and briefly cached. The existing host account is selected by the helper and real repository write permission is still checked.
- Actual machine finding: Git is present in the development runtime, not a normal installed Windows Git location. Native Electron without Git in PATH reproduced online=true/writable=false. Windows fallback reads only existing current-user GitHub host/owner credential targets using CredReadW, frees returned buffers, has a five-second process deadline and never enumerates/writes credentials, prompts, logs tokens or puts secrets into arguments. The same native read-only status test with final compiled application code now returns online=true/writable=true without Git in PATH. Proof: `work/v98-native-cloud.json`. No test media was uploaded to the shared repository; actual upload requests and denial paths are tested against simulated responses.

Native credential implementation reference: [Microsoft CredReadW](https://learn.microsoft.com/windows/win32/api/wincred/nf-wincred-credreadw), [CREDENTIALW](https://learn.microsoft.com/windows/win32/api/wincred/ns-wincred-credentialw), and [Git Credential Manager storage configuration](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/configuration.md). Other accounts still require valid existing credentials and actual repository permission; this fix grants no permissions.
