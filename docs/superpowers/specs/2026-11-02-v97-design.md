# v97: reliable live operation and local slide drafting

Status: approved by the user on 2 November 2026: on-demand local model download, offline drafting, initially OFF AIR, plus latency/startup/audio improvements. Root implements natively.

## Intent and scope

The user accepted the three recommended priorities: measure live delivery latency, improve startup reliability, and expand audio testing with visible levels. They additionally requested AI-created slides with content and selected local processing over an online API. Existing visitor designs, live snapshots and output assignments remain intact.

## Approaches and decisions

For slide generation, an online API offers remote compute but needs connectivity and potentially paid credentials; the user selected local execution instead. A separate local inference server would add installation and setup. Proposed approach: reuse the existing Transformers.js dependency with an independently executed small, pinned text model and an in-app downloadable pack, then generate normal editable slide objects through the existing document model. No template-only generator may be presented as model-generated text. Exact model selection requires compatibility, license, integrity and real German-output evaluation before adoption.

The inspected machine has approximately 8 GB physical RAM. The proposed default is a small quantized model, loaded only on demand and released after use; model work must remain outside the operator render path. An optional download is proposed, not yet approved as a distribution choice. No third-party application or API account is required. Internet is needed for the initial model acquisition only; prompts remain local. No generation starts at application startup. Generation during ON AIR is disabled initially to preserve live resources; reviewed drafts can still be inserted for later use.

## Slide creation flow

Element hinzufügen → Mit KI erstellen. Enter topic or supplied notes, intended use and a bounded slide count. Draft titles and short bodies, then apply existing theme-based layouts. Show rendered previews with editable content, retry and cancel. Explicit acceptance inserts a batch into the selected valid section as a single undoable edit. Selection is not live; generation or acceptance must never take a slide to MAIN. Decline or cancellation leaves the document unchanged. Do not fabricate Bible quotations: supplied exact scripture can be preserved, otherwise references require existing Bible lookup or operator review. Generated content is a draft, not an authoritative Bible source.

Download state, progress, cancellation, storage removal, insufficient resources and generation errors belong in operator UI. Downloads must be pinned and integrity-checked; partial files cannot be marked ready. Closing the draft dialog stops inference and discards its ephemeral work. No generated HTML/script, arbitrary file access, shell commands or model-triggered actions.

## Live timing

Extend existing revision-based output delivery with bounded diagnostics keyed by the actual take and output role. Measure preparation/send, receiver receipt and post-render acknowledgement, plus local preview rendering. Reject stale, unowned or mismatched acknowledgements. Distinguish app-render acknowledgement from physical panel scanout; do not claim a software timestamp measures HDMI display latency. Diagnostics are lightweight and avoid per-frame application-wide updates. Use measurements to reproduce and fix actual divergence rather than introducing guessed delays.

## Startup

Existing startup intentionally waits for document loading and crash-recovery decisions. Preserve that ordering to prevent late restoration overwriting edits. Investigate optional display/version/connectivity work currently included in the authentication readiness group, and decouple only work not needed for a safe editor. Show actual phase status and bounded retry behavior. Preserve authentication requirements, output geometry and the existing delayed update notification policy. No speculative reduction of safety waits without regression evidence.

## Audio

Extend existing BackgroundAudioHealth, AudioLevelProvider, route tests and announcement probe rather than introduce another engine. Show measured levels, selected route/device, mute and effective volume for supported paths; label unavailable signal analysis honestly. Provide explicit start/stop for tests with route ownership and cleanup. Measurements never connect an extra audible destination, change routing, restart existing media or claim that a nonzero software meter proves physical speaker output.

## Verification and delivery

Root implements and reviews code; only translation work may be delegated. Preserve the unrelated untracked startup diagnostic. Write meaningful regression tests for lifecycle, ownership, cancelled generation, malformed output and unchanged live state. Use actual Electron fixtures for output acknowledgements, startup and audio analysis. Run a real pinned-model German drafting probe and inspect generated slides, including offline rerun, cancellation and resource release. Complete regional strings/help/release documentation under the existing strict completeness gate. Normal publication follows full tests, native regressions, all-platform packaging and public updater/installer verification.

## Open approval

The user confirmed the on-demand in-app model download and initial OFF AIR generation restriction. This design does not assert a model has been downloaded, benchmarked or integrated.
