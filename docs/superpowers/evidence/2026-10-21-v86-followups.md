# v86 approved reminder, ribbon and announcement follow-ups

## Approved behavior

The user confirmed the one-time OFF-AIR reminder, larger symmetric ticker gaps
and slow announcement round trip. No interim publication is authorized: the
earlier instruction to wait for complete regional coverage and PowerPoint stays.

- Reminder is operator-only, once per linked event key/effective start in this
  app session, within the 20 minutes before start. It uses the central event
  runtime and EventService effective time. ON AIR hides it immediately. Missing,
  cancelled, trashed or already-started events cannot trigger it. It does not
  start outputs, change ON AIR, bypass preflight or play audio. A delayed start
  is recalculated; renaming an event does not reset acknowledgement.
- Ticker separator has sixteen preserved spaces on each side of the middle dot.
  The same measured separator is used between messages and at the repeat seam;
  no additional repeat gap or PRE/countdown clock reset is introduced.
- Long announcement bodies use a shared-clock down/up scroll at 20 presentation
  pixels/second with five-second endpoint pauses. Title and QR remain fixed.
  Minimum hold covers the complete round trip. Existing event-table scrolling
  is unchanged. Reduced motion keeps the existing stepped alternative.
- New reminder text and changed scroll guidance are authored in all 15 approved
  regional packs, with DE/EN base templates. Root verified each pack changed
  exactly those three keys and preserved `{minutes}`. No speech/public text is
  regionalized, no native dialog/resource fields were replaced.

## Review scope

Root author self-review, not independent review, consistent with the user's
translation-only delegation restriction. Checked operator-only mounting, no
Firebase writes, ON AIR suppression, effective-time changes, once-only identity,
scroll timing parity, stable QR/title geometry and measured ticker seams.
No remaining critical issue found in these bounded changes. This is not a
completion assessment for all of v86.

The reminder does not notify while the application is closed and is not an
OS scheduled notification. Its once-only acknowledgement lasts for the current
mounted application session, not across process restarts. Those behaviors were
not requested and are not silently claimed.
